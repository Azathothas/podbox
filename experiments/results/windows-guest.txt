== the guest's own exit code
command  mb run /tmp/e2e/prov.qcow2 /tmp/e2e/r4.qcow2 "ver >nul & cmd /c exit 42"
output   REQUEST TOKEN c19bae3970cca0da351999c33dff3ab5
         EXIT 42 token true in 29s
         STDOUT=""
         STDERR=""
         MB WQCODE.TXT: 42 c19bae3970cca0da351999c33dff3ab5||
note     42 is the guest's code, and the mailbox line is the pair the host
         read it from. `podbox_windows::cap_status` passes 0..=124 through and
         reports 125 for anything above, which is why 42 arrives intact.

== a wrong token is refused, against the mailbox above
command  mb stale /tmp/e2e/prov.qcow2 /tmp/e2e/r4.qcow2
output   STALE REFUSED: the mailbox holds a result for token
         "c19bae3970cca0da351999c33dff3ab5", not "0000...0000"
note     the anti-replay rule, verified against a real guest-written result
         rather than a fixture.

== a command that prevents the agent from finishing
command  mb run /tmp/e2e/prov.qcow2 /tmp/e2e/r2.qcow2 "ver >nul & exit 42"
output   RUN FAILED in 300s: the guest did not power off within 300s, so it
         was stopped
note     `exit` (not `exit /b`) inside the command file terminates the
         agent's own cmd.exe, so no WQCODE is ever written and the run is
         refused. This is the intended behaviour - a timeout is never an
         empty success - and is recorded because it is the one way a caller
         can make a run unanswerable.

== two runs that measured the lane, not the code
⚠ Two earlier runs of the same `cmd /c exit 42` command also timed out at
300s and then completed in 29s once `/tmp` was freed. The lane was at 100%
of its 489 MiB tmpfs while they ran, and the mailbox is mounted
`cache=writethrough`, so the host saw ENOSPC on the guest's writes. This is
recorded as a property of running a guest in a small tmpfs, not as a defect
in the driver; the driver refused in both cases rather than reporting a
result it did not have.
