## The structural change

| fact | line | consequence |
| --- | --- | --- |
| `podbox-cli` targets are `['bin','custom-build']` | `cargo metadata` | no `lib`, so no `use podbox_cli::…` in a test |
| `crates/podbox-ssh/tests/common.rs` exists | the only `tests/` directory | its idiom is the model for the new ones |

Two shapes are available for `podbox-cli`:

- **Black-box.** A `tests/*.rs` that drives the built binary through
  `env!("CARGO_BIN_EXE_podbox")`. Proves the real default path, which is what
  `docs/conventions/code.md:29` asks of an integration test. Slower, and it needs
  a working binary.
- **Library.** Add `[lib]` to `crates/podbox-cli/Cargo.toml` and test through the
  crate's own API. Faster, but it adds an export surface and a release artefact
  that did not exist.

For a behaviour the operator sees at the command line, black-box is the better
proof. This entry says so; an implementor may argue otherwise with the reason
recorded.
Batch 0 decision, recorded 2026-10-01. D-5: all `podbox-cli` integration
files drive the built binary black-box through `CARGO_BIN_EXE_podbox`. No
`[lib]` is added: it opens an export surface and a release artefact for test
convenience. Clauses needing internals stay unit tests in `src/`. T-1532
confirms the shape per file and re-opens with evidence if one file cannot be
written black-box.

## The registry fixture

`serve_once` cannot serve it. A fixture needs:

- bind an ephemeral loopback port and report it,
- hold a push and a pull target,
- answer the manifest GET, the blob GET and the blob HEAD that
  `crates/podbox-image/src/store.rs` issues,
- return an ETag and a digest the client can check,
- shut down so the test does not leak a listener.

Place it where both the store tests and the image tests can use it:
`crates/podbox-image/tests/common/registry.rs`, wired by a `mod common;` in each
test that needs it, following `crates/podbox-ssh/tests/common.rs`.

⛔ **Do not build a full OCI registry.** The fixture serves what podbox's client
actually requests and nothing more. `docs/conventions/code.md:13` forbids
speculative machinery with no caller.
